# Whole board focused mesh verification

The October 1, 2026 checkpoint verifies bounded normalized planar PCB compilation,
selection-driven sizing and actual native tetra generation. It does not qualify
general PCB field extraction or SI, EM and thermal accuracy. Original fixtures
and test doubles were independently authored; external example/source code was
not adapted.

## Native fixture

The original `examples/pcb_focus_mesh/whole_board.json` declares a concave board
with a cutout, five contiguous slabs, three nets, polygon copper/antipads and
through/blind/buried via spans. Its exact exterior volume is
`(12*8 + 8*2 - 1) * 1.55 = 172.05 mm^3`. Internal drill volumes are included as
air, not deleted cells. All 15 compiled sources and all three nets have actual
tetrahedral coverage in every case.

The admitted Gmsh 4.15.2 runtime ran in Windows build 26200 under CPython 3.11.9
with NumPy 2.2.6 and Shapely 2.1.2. Actual outputs are in
`build/pcb-focus-mesh-qualified-20261001-v2/`, generated by the checked-in example
runner. `evidence.json` records source hashes, request/mesh hashes, geometry
checks and comparisons; `sha256.json` covers the generated artifacts. Each case
includes `request.json`, `prepared.json`, `result.json`, `mesh.msh`, process/log
evidence and its native hash manifest. The top-level manifest also covers the
prepared file added after the native runner's per-case manifest.

The distant window is explicitly `x < 5, y > 7, 0.6 < z < 1.4` in FR4, outside
the local boxes. Focused cases have at least twice the baseline median edge
there and fewer total cells; the runner asserts both. This is evidence for this
fixture, not a guaranteed savings factor on arbitrary boards. Elapsed case
times were 3.02, 3.06, 3.17 and 6.32 seconds in a single run. No warm-up/median
performance qualification or general speedup is claimed.

Relative exterior-volume errors are at most 1.67e-15 against the analytical
union. Boolean source volumes are conserved at admission, and every fragment
has positive represented mesh volume. Linear via/drill source volumes differ
from analytic CAD by up to 1.859%; this error does not disappear just because
the total board volume agrees. Minimum mean-ratio qualities are respectively
0.0074932, 0.0074820, 0.0083880 and 0.00073689. These thin-layer/sliver quality
values need solver conditioning/convergence assessment, not a passing-quality
label.

Longest-edge requested-target diagnostics report 3,972, 3,407, 5,134 and 35,075
cells above target. Maximum ratios are approximately 2.4103, 2.4100, 2.3808 and
2.1063. Gmsh sizing is not a strict longest-edge bound, and the diagnostic box
formula is not proof of its realized field. No size requirement was waived.

All four processes returned zero with private-memory enforcement and race-closed
Job assignment. The venv host launched the base interpreter with `-I -S` and
configured dependency directories, without relaxing the one-process Job limit.
Entry API/DLL hashes and interpreter hashes are in the artifacts. Full transitive
DLL admission, redistribution and filesystem/network sandboxing remain absent.

## Tests and audit feedback

Focused checks cover strict schemas and offline reference resolution, unknown
selectors/fields, resource rejection, whole-model identity under every selection,
fixed numeric fields, compact diagnostics and JSON-line preparation. Analytical
sizing/BVH tests cover transitions, metre conversion, exact direct-minimum
agreement, translated small geometry and contours beyond 2,048 points.

Independent review found and corrected: a missing fixture antipad; an obsolete
2,048-point focus limit; unrecentered polygon-area cancellation; unrepresentable
transition thickness; and a false retention claim for an entirely unmeshed CAD
fragment. The last has an original two-prism regression with empty native element
records. The global lower-size clamp was also corrected after native overlapping
facet failure on small curved features. No failed partial mesh was accepted.

The main Python 3.12 environment passed 87 generator/adaptation/refinement/
optimization/compiler/focus/preparation/OCC tests with warnings as errors.
A separate Python 3.11 run passed 35 focus/compiler/OCC/coverage/runtime tests;
the main environment additionally passed 10 preparation and tetra-worker routing
tests. Suites overlap and their counts must not be added as unique coverage.
The architecture guard passed.
After the final launcher/probe regression additions, the combined main-environment
meshing run reported 97 tests with five Python 3.11-only skips and no failures
or errors; seven narrow launcher/runtime tests passed under Python 3.11. Counts
include overlapping earlier checks. The capability probe reports missing Shapely
as unavailable instead of promising preparation/execution.

Full Python regression discovery ran 2,297 tests in 401 seconds: one failure,
11 skips, no errors. The failure also reproduces alone in
`test_public_release_readiness.test_current_candidate_is_technical_but_externally_blocked`:
the test expects `PUBLIC_RELEASE_DEPENDENCY_APPROVAL_REQUIRED`, but the current
release evaluator no longer emits it because the concurrently maintained notices
lack its `register is incomplete` sentinel. Release files/tests were not changed
to mask that failure. Full-suite qualification is not green.

The special Python 3.11 EMerge environment lacks `jsonschema` for the complete
service: a broader service/schema attempt there failed for that missing dependency.
Native isolated examples passed there; full JSON-line preparation passed in the
main environment. Packaging must provide and qualify one complete admitted worker
environment before describing both operations as a deployable workflow.

## Reproduction and remaining work

Use the [workflow](../PCB_FOCUSED_VOLUME_MESHING.md) and run the original example
into a new directory. Requests, results and source snapshots are hashed; source
changes during a run reject its evidence. Unit tests are in `tests/python/test_pcb_*`
and `test_gmsh_occ_*`; internal adaptation tests remain separate.

The shared ownership/interface contract supports compatible SI/EM/thermal adapter
inputs. It does not provide ports, excitations, PDE estimators or measured data.
Automatic EDA conversion, bent/curved assemblies, large-board budgets, curve/shape
improvement, global intersection checks, physics convergence, Linux/native/MPI
qualification and clean-machine packaging remain open. This does not repair or
requalify the separate Marble PEEC accuracy defect. Human numerical review remains
required before release.
