# Engineering report presentation verification — 2026-10-03

## Scope and changes

Engineering PI, SI, thermal and EM reports share an offline HTML presentation
with a sticky section sidebar, direct per-net links, collapsible contents on
narrow windows, readable tables and bounded visualization controls. The AC PI,
SI channel and Optycal exports use the same presentation.

Print output contains an opening cover, linked contents, scope, saved setup,
all net records sequentially, static board/curve figures, warnings,
traceability and closing conclusions. A4 landscape accommodates wide tables;
Chromium page margin boxes provide headers and page counts. Other print engines
and user-selected paper sizes still need print-preview review.

The interactive report runtime redraws after positive canvas sizing and visible
section changes. Static SVG figures remain available when scripts are disabled
and for printing. No solver samples are generated by these changes. Failed
partial results remain excluded from numerical presentation; unvalidated model
states remain visibly unvalidated. Saved form settings do not establish the
provenance of a returned result.

## Acceptance evidence

- `npm run test:report-runtime`: executable runtime sizing/navigation checks,
  component thermal blocked states, preview window lifecycle, four engineering
  domain fixtures, secondary reports and AC report setup/escaping/plots passed.
- `npm run test:pi-review-admission` and `test:si-channel-results`: failed
  evidence admission and existing SI result contracts passed.
- `npm run build`: TypeScript and production frontend build passed. Existing
  large-chunk and mixed static/dynamic import warnings remain.
- Architecture check and parser regression passed. Help reference, control
  inventory and help link/asset checks passed.
- `cargo test --offline`: 35 passed, one optional live OS counter test ignored.
  The first attempt exhausted disk space. Removing one obsolete SPIKE Rust
  incremental cache allowed the retry to pass; source and project data were
  preserved.

Browser checks used the generated, explicitly synthetic UI fixture at
`app/scripts/fixtures/engineering-report.html`. At 1400 × 880 CSS pixels, clicking
the VDD_IO sidebar link selected only its panel and navigated to its anchor;
the visualization had a positive-size canvas and `data-render-ready=true`.
At 720 × 720, the contents disclosure collapsed, setup changed to a single
column, and document width remained within the viewport. Wide tables scroll
within their own region.

An isolated local Chromium print renderer generated the PI fixture PDF with
JavaScript disabled. The output has 16 pages and 50 linked annotations and
includes both net names, setup, static figures and conclusions. All pages were
visually reviewed; the final affected numerical/validity pages were rendered
again after pagination corrections. The fixture is not physical or numerical
validation evidence.

Local ignored review artifacts are under `build/report-layout-20261003/`:
`report-fixture-pi.pdf`, HTML fixtures, `html-sidebar-visualization.jpg`,
`html-net-review.jpg` and `html-narrow.jpg`.

## Limits

Native window movement and the actual WebView print dialog remain unverified:
the authorized native automation helper could not bind the development SPIKE
window. Browser rendering and offline PDF rendering were verified separately.
No new physical analysis or solver validation was performed.

The full Python suite ran 2395 tests in 523.804 seconds: one failure, two
errors and 13 skips. The failure is the existing release-readiness assertion
expecting `PUBLIC_RELEASE_DEPENDENCY_APPROVAL_REQUIRED`. The two errors could
not open the default model-library SQLite cache in the restricted environment.
Both affected model-library tests passed when rerun with
`SPIKE_MODEL_INDEX_PATH` set to an isolated writable workspace test cache.
The full suite is therefore not reported as passing. The log is
`build/report-layout-20261003/python-suite.log`.
