# SPIKE 0.3.4 - early community preview

SPIKE's development effort is largely **LLM-driven under human review**. This
is a very early release: instabilities, bugs, inaccurate outputs and incomplete
workflows may occur. The community is invited to test it and provide feedback.
Human review and passing automated checks do not establish independent physical
validation or production qualification of every solver.

## Packaging correction

The unpublished v0.3.2 candidate failed frozen-worker extension checks. This
release includes the ODB++ source-inspection module in the frozen worker and
checks step inspection through the actual bundled extension host before
packaging. The failed candidate remains tagged; its binaries were not published.

The v0.3.3 candidate passed Linux and macOS package checks but its Windows
installer verification counted auxiliary executables as desktop apps. This
release selects the known desktop entrypoint explicitly, rejects missing or
nested substitutes, and retains installed startup, reinstall and uninstall
checks. Two Windows path-selection regression tests pass.

## What changed

- Expanded multiboard assembly workflows: retain board sources, add local board
  occurrences, duplicate and remove boards, edit placement, define explicit
  connector/harness links and inspect occurrence-scoped layers and nets.
- Improved viewport controls, model resolution, tool windows, shared control
  styling and report navigation.
- Expanded the Python workspace with file management, templates, completions
  and a dedicated SPIKE API.
- Added experimental coupled board/structure circuit, thermal-network and
  magnetic-loop studies, plus supplied-volume steady thermal and electrothermal
  workers with explicit occurrence and source bindings.
- Added `.spike` and standalone field-study setup/results storage, with
  manifest-bound reads and stale-result withholding.
- Updated development disclosures, capability limits and reproducible evidence.

## Scope and known limitations

Reduced assembly circuits, thermal networks and magnetic-loop models are
experimental. The retained-volume thermal workflow requires caller-supplied
conforming meshes; source/stack hashes are declarations. General automatic
board/casing volume extraction, coupled field radiation, and general assembly
Maxwell/SI execution remain pending. Electrothermal workers have a separate
contract and are not integrated into the thermal-only field-study editor.
Optional solver engines have their own installation and capability limits.

Native visual acceptance of the new field editor, clean-machine behavior for
all new workflows, independent measured correlation and production numerical
qualification remain incomplete. Read the versioned Solver Status and feature
documentation before relying on a result.

The integrated source baseline completed 2,573 tests with no failures and 13 skips,
using the project virtual environment and a writable model index. The native
Rust host checks passed (38 tests, one live OS counter check ignored). Frontend
build, parser, assembly, report, help, control styling, architecture and release
automation checks passed. Package-build and platform smoke results are separate
evidence from these source checks.

The packaging corrections passed 24 focused tests. The ODB++ correction passed
a fresh local Windows frozen-worker build, including actual bundled inspection,
import, harness and MCAD extension probes. Platform release jobs rebuild their
own native libraries and packages from the release commit.

## Downloads and package checks

The release workflow publishes packages only after all required platform builds
and checksum checks succeed: a Windows x64 installer, an experimental Linux
x86-64 Flatpak, and experimental macOS DMGs for Apple Silicon and Intel.
SHA-256 files accompany each package. The Windows installer is unsigned; macOS
packages are ad-hoc signed without Apple notarization.
